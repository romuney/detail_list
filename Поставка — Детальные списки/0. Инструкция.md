# Детальные списки — что куда вставлять

Две вкладки одного борда — **«Детальные списки»** (параллельная структура) и **«Детальные
списки КП»** (каталог продуктов). На каждой вкладке два чарта: **строка фильтров** сверху (все
фильтры в два компактных ряда, выпадашка — широкая, поверх списка) и **список** под ней. Нативные
фильтры борда не нужны. Прежние датасеты и чарты не трогаются — новое заводится рядом, старый борд
работает, пока идёт проба на копии.

| Файл | Куда вставлять |
|---|---|
| `1. Датасет «Детальные списки».sql` | новый виртуальный датасет `detail_list`, база CROSS → SQL |
| `2. Датасет «Детальные списки КП».sql` | новый виртуальный датасет `detail_list_kp` |
| `3. Датасет «Детальные списки: фильтры».sql` | новый виртуальный датасет `detail_list_flt` |
| `4. Датасет «Детальные списки КП: фильтры».sql` | новый виртуальный датасет `detail_list_kp_flt` |
| `5. Чарт «Детальные списки».js` | чарт «Детальные списки» (ECHARTS) на `detail_list` → JS |
| `6. Чарт «Детальные списки КП».js` | чарт «Детальные списки КП» на `detail_list_kp` → JS |
| `7. Чарт «Детальные списки: фильтры».js` | чарт «Детальные списки: фильтры» на `detail_list_flt` → JS |
| `8. Чарт «Детальные списки КП: фильтры».js` | чарт «Детальные списки КП: фильтры» на `detail_list_kp_flt` → JS |
| `9. CSS борда.css` | Edit dashboard → CSS, в конец; id четырёх чартов вместо `000000`…`333333` — **обязательно** |

Датасеты 1–4 — один SQL, отличаются строками `MODE` (вкладка) и `VIEW` (чарт); JS 5–8 — два
файла, отличаются строкой `ns`. Пары не путать: у каждого чарта свой JS и свой датасет.

## Как это работает

- **Строка фильтров** — 33 фильтра в разделах и порядке нативных фильтров 7241.
  - «Период» (последний день / на дату), «Численность», «Тип ЮЛ».
  - «Юнит УС», «Юнит ЮС», «Продукт КП» — дерево всех уровней с поиском по названию на любом
    уровне; заменяют «Кросс-фильтр по …» и «Уровень 3…13».
  - 26 атрибутов.
  - «Сотрудники по списку» — вставка MasterID, логинов, табельных или Siebel ID.
  - Выбор копится (набранное — пунктиром) и уходит одной кнопкой «Применить · N» — в строке и в
    выпадашке. «Отменить» возвращает применённое, «Сбросить» снимает всё.
- **Список:**
  - Итог «N сотрудников» и первые 5 000 сотрудников по MasterID ↑; «Загружать» — 5 000 / 10 000
    / 25 000.
  - Под фильтрами больше 25 000 — жёлтая плашка «сузьте фильтры»; до 25 000, но больше
    загруженного — «Загрузить всех».
  - Сортировка: все загружены — сразу; нет — запрос «первые N по этой колонке».
  - Без запроса: страницы, поиск по таблице, группировка (до 3 уровней), перестановка и ширина
    колонок, «Копировать» — все загруженные строки (с учётом поиска) для Excel.
- **Доступ — как раньше.** warden по логину маскирует персональные данные, грейд, сеньорность и
  оценку: в ячейке «⛔ нет доступа», в «Копировать» — прежний текст. Логина нет в warden — плашка
  вместо списка и вместо фильтров.
- **КП.** Показана аллокация или уровень КП — блок сотрудника (строка на аллокацию), иначе строка
  на сотрудника. «Суммарная аллокация» и «Кол-во аллокаций» считает чарт.

## 3. Чарты

Для каждого из четырёх:

1. Новый чарт на своём датасете (таблица выше), тип **ECHARTS** (кастомный JS).
2. **Измерения** — `role  k  v  n  j`, точными именами. Мер и сортировки нет. **Лимит строк —

3. JS — свой файл целиком. Сохранить.

## 4. Кросс-фильтры: кто кого фильтрует

Строка фильтров фильтрует себя (счётчики) и список своей вкладки. Список фильтрует только себя
(сортировка, лимит, колонки). Без этого «Применить», колонки, сортировка и лимит не работают —
через 30 секунд чарт скажет жёлтой плашкой. Настраивается JSON-метаданными дашборда:

1. **id чартов:** меню чарта «⋮» → «Редактировать график» — число после `slice_id=` в адресе.
   Ниже:
   - `ID1` — «Детальные списки»;
   - `ID2` — «Детальные списки КП»;
   - `ID3` — «Детальные списки: фильтры»;
   - `ID4` — «Детальные списки КП: фильтры».
2. Дашборд → «…» → «Редактировать свойства» → «Дополнительно» → «JSON метаданные».
3. `"cross_filters_enabled": true` (нет ключа — добавьте строку).
4. Блок `"chart_configuration"` замените целиком (нет — добавьте):
   ```json
   "chart_configuration": {
     "ID1": {"id": ID1, "crossFilters": {"scope": {"rootPath": ["ROOT_ID"], "excluded": [ID2, ID3, ID4]}, "chartsInScope": [ID1]}},
     "ID2": {"id": ID2, "crossFilters": {"scope": {"rootPath": ["ROOT_ID"], "excluded": [ID1, ID3, ID4]}, "chartsInScope": [ID2]}},
     "ID3": {"id": ID3, "crossFilters": {"scope": {"rootPath": ["ROOT_ID"], "excluded": [ID2, ID4]}, "chartsInScope": [ID1, ID3]}},
     "ID4": {"id": ID4, "crossFilters": {"scope": {"rootPath": ["ROOT_ID"], "excluded": [ID1, ID3]}, "chartsInScope": [ID2, ID4]}}
   },
   ```
   - По умолчанию в `excluded` стоит сам чарт, и свой фильтр до него не доходит — здесь его там
     нет ни у одного.
   - В ключах `"ID1"`… числа в кавычках, в остальных местах — без.
   - Носители у вкладок разные (`…_f` и `…_kf`): если область окажется шире, данные не
     перепутаются, лишь добавятся лишние запросы.
5. Сохранить свойства → «Сохранить» дашборд → обновить страницу.

## 8. Если что-то не так

| Симптом | Причина и что сделать |
|---|---|
| «Некорректный SQL запрос: →…←» при сохранении датасета | вставлен SQL прежней поставки или текст правили руками — файл целиком из этой поставки; не помогло — прислать фрагмент между стрелками |
| Выпадашка обрезана по высоте строки фильтров | CSS файла 9 не добавлен или id не заменены (`222222`, `333333` — id строк фильтров) — п. 5 |

| «Применить» — список не меняется, через 30 с жёлтая плашка | строка фильтров не фильтрует список или себя — п. 4 (`chartsInScope` у ID3 / ID4) |
| Жёлтая плашка в списке «Ответа нет 30 секунд…» при сортировке или колонках | список не фильтрует сам себя — п. 4 (`chartsInScope` у ID1 / ID2); на тяжёлом запросе (КП, 25 000) — запрос ещё идёт |
| Жёлтая плашка «Под фильтрами больше 25 000…» | так задумано: в таблицу помещается до 25 000 — сузьте фильтры |
| «В данных чарта нет колонок: …» | не все 5 полей в «Измерениях» или не синхронизированы столбцы — п. 1.3, 3.2 |
| «Нет служебной строки meta» | мал лимит строк — п. 3.2 |
| «Фильтры не применились: нет applyCrossFilter» | чарт открыт вне дашборда (в редакторе) — там фильтры не работают |
| «Для вашего логина нет строки в таблице доступа warden» | логина нет в `warden_access_array_cross` — как и у прежнего чарта |
| «Значений в фильтрах — не больше 200 у атрибута и 500 всего» | предел длины запроса ClickHouse; для длинных списков сотрудников — «Сотрудники по списку» (до 2 000) |
| Ошибка ClickHouse о колонке | колонка источника переименована — сверьте с прежним датасетом: новый читает те же колонки |
