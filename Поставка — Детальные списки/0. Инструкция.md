# Детальные списки — что куда вставлять

Две вкладки одного борда — **«Детальные списки»** (параллельная структура) и **«Детальные
списки КП»** (каталог продуктов). На каждой вкладке два чарта в одном ряду: **панель фильтров**
слева (разделы, в разделе по два фильтра в ряд; выбрали значение — остальные фильтры сразу, ещё до
«Применить», показывают, что под ним осталось; выпадашка — широкая, вправо поверх списка) и
**список** справа. Нативные фильтры борда не нужны. Прежние датасеты и чарты не трогаются — новое заводится рядом, старый борд
работает, пока идёт проба на копии.

| Файл | Куда вставлять |
|---|---|
| `1. Датасет «Детальные списки».sql` | новый виртуальный датасет `detail_list`, база CROSS → SQL |
| `2. Датасет «Детальные списки КП».sql` | новый виртуальный датасет `detail_list_kp` |
| `3. Датасет «Детальные списки: фильтры».sql` | новый виртуальный датасет `detail_list_flt` |
| `4. Датасет «Детальные списки КП: фильтры».sql` | новый виртуальный датасет `detail_list_kp_flt` |
| `5. Чарт «Детальные списки».js` | чарт «Детальные списки» (ECHARTS) на `detail_list` → JS |
| `6. Чарт «Детальные списки КП».js` | чарт «Детальные списки КП» на `detail_list_kp` → JS |
| `7. Чарт «Детальные списки: фильтры».js` | чарт «Детальные списки: фильтры» на `detail_list_flt` → JS |
| `8. Чарт «Детальные списки КП: фильтры».js` | чарт «Детальные списки КП: фильтры» на `detail_list_kp_flt` → JS |
| `9. CSS борда.css` | Edit dashboard → CSS, в конец; id четырёх чартов вместо `000000`…`333333` — **обязательно** |

Датасеты 1–4 — один SQL, отличаются строками `MODE` (вкладка) и `VIEW` (чарт); JS 5–8 — два
файла, отличаются строкой `ns`. Пары не путать: у каждого чарта свой JS и свой датасет.

## Как это работает

- **Панель фильтров** — 33 фильтра в разделах и порядке нативных фильтров 7241, по два в ряд.
  - «Период» (последний день / на дату), «Численность», «Тип ЮЛ».
  - «Юнит УС», «Юнит ЮС», «Продукт КП» — дерево всех уровней с поиском по названию на любом
    уровне; заменяют «Кросс-фильтр по …» и «Уровень 3…13».
  - 26 атрибутов.
  - «Сотрудники по списку» — вставка MasterID, логинов, табельных или Siebel ID.
  - Число у значения — сотрудники при остальных фильтрах, по набранному выбору, сразу; внизу —
    «Будет N». Выбор копится (набранное — пунктиром) и уходит одной кнопкой «Применить · N» — в
    панели и в выпадашке. «Отменить» возвращает применённое, «Сбросить» снимает всё.
- **Список:**
  - Итог «N сотрудников» и первые 5 000 сотрудников по MasterID ↑; «Загружать» — 5 000 / 10 000
    / 25 000.
  - Под фильтрами больше 25 000 — жёлтая плашка «сузьте фильтры»; до 25 000, но больше
    загруженного — «Загрузить всех».
  - Сортировка: все загружены — сразу; нет — запрос «первые N по этой колонке».
  - Без запроса: страницы, поиск по таблице, группировка (до 3 уровней), перестановка и ширина
    колонок, «Копировать» — все загруженные строки (с учётом поиска) для Excel.
- **Доступ — как раньше.** warden по логину маскирует персональные данные, грейд, сеньорность и
  оценку: в ячейке «⛔ нет доступа», в «Копировать» — прежний текст. Логина нет в warden — плашка
  вместо списка и вместо фильтров.
- **КП.** Показана аллокация или уровень КП — блок сотрудника (строка на аллокацию), иначе строка
  на сотрудника. «Суммарная аллокация» и «Кол-во аллокаций» считает чарт.

## 4. Кросс-фильтры: кто кого фильтрует

Панель фильтров фильтрует только список своей вкладки (сама себя — нет: её числа считаются в браузере).
Список фильтрует только себя (сортировка, лимит, колонки). Без этого «Применить», колонки, сортировка и
лимит не работают —
через 30 секунд чарт скажет жёлтой плашкой. Настраивается JSON-метаданными дашборда:

1. **id чартов:** меню чарта «⋮» → «Редактировать график» — число после `slice_id=` в адресе.
   Ниже:
   - `ID1` — «Детальные списки»;
   - `ID2` — «Детальные списки КП»;
   - `ID3` — «Детальные списки: фильтры»;
   - `ID4` — «Детальные списки КП: фильтры».
2. Дашборд → «…» → «Редактировать свойства» → «Дополнительно» → «JSON метаданные».
3. `"cross_filters_enabled": true` (нет ключа — добавьте строку).
4. Блок `"chart_configuration"` замените целиком (нет — добавьте):
   ```json
   "chart_configuration": {
     "ID1": {"id": ID1, "crossFilters": {"scope": {"rootPath": ["ROOT_ID"], "excluded": [ID2, ID3, ID4]}, "chartsInScope": [ID1]}},
     "ID2": {"id": ID2, "crossFilters": {"scope": {"rootPath": ["ROOT_ID"], "excluded": [ID1, ID3, ID4]}, "chartsInScope": [ID2]}},
     "ID3": {"id": ID3, "crossFilters": {"scope": {"rootPath": ["ROOT_ID"], "excluded": [ID2, ID3, ID4]}, "chartsInScope": [ID1]}},
     "ID4": {"id": ID4, "crossFilters": {"scope": {"rootPath": ["ROOT_ID"], "excluded": [ID1, ID3, ID4]}, "chartsInScope": [ID2]}}
   },
   ```
   - Списки (ID1, ID2) фильтруют сами себя — в их `excluded` себя нет. Панели (ID3, ID4) — только
     свой список: сами они в своём `excluded` есть.
   - В ключах `"ID1"`… числа в кавычках, в остальных местах — без.
   - Носители у вкладок разные (`…_f` и `…_kf`): если область окажется шире, данные не
     перепутаются, лишь добавятся лишние запросы.
5. Сохранить свойства → «Сохранить» дашборд → обновить страницу.

## 5. CSS борда (обязательно)

Файл 9 целиком в конец CSS дашборда. Замените во всех местах (Ctrl+H):

- `000000` → `ID1`;
- `111111` → `ID2`;
- `222222` → `ID3`;
- `333333` → `ID4`.

Без блока 4 файла выпадашки панели фильтров открываются поверх самой панели (узко), а не справа от неё. Красные «!» редактора у
строк с `:has(...)` — линтер не знает `:has`, на работу не влияет.

   - Список: «84 875 сотрудников · в таблице первые 5 000 по «MasterID» ↑» (ваше число), две
     колонки, плашка «больше 25 000 — сузьте фильтры».
   - Панель фильтров: разделы, по два фильтра в ряд, внизу «Под фильтрами N».
   - Время: список — главное (на стенде ≈0,3 с), панель приходит следом (на стенде ≈3,5 с).
2. **Выпадашка.** «Юнит УС» → широкая выпадашка справа от панели, поверх списка, сразу, без
   «Загружаю»; поиск «инвест» — находки с путём. Отметить → внизу «Будет N», «Применить · 1».
3. **Каскад до «Применить».** Не применяя, открыть «Стрим» — числа уже под выбранным юнитом, в
   сумме = «Будет N». «Применить» → список «Обновляю…» → итог списка = N.
4. **Закрытие.** Esc, клик мимо (по списку) — выпадашка закрывается, клик в список не
   проходит.
5. **Колонки и таблица.** «Колонки» → «Рабочие данные» → «Показать» — один короткий запрос; снять
   колонку — сразу. Клик по заголовку — сортировка; перетащить — порядок; край — ширина.
6. **«Загружать» и «Копировать».** «Загружать: 25 000», «Копировать» → вставить в Excel: даты
   ДД.ММ.ГГГГ, стаж с запятой.
7. **Сотрудники по списку.** Вставить несколько MasterID → «Применить».
8. **Вкладка КП.** Блоки сотрудников, «КП-разрез», «Продукт КП».
9. **Доступ.** Логин без строки в warden — плашки; частичный доступ — «⛔ нет доступа» в скрытых
   полях.

## 7. Замена на проде

Когда проба прошла:

1. На боевом дашборде — четыре датасета и четыре чарта, как в п. 1–3; панели фильтров — слева
   от списков.
2. JSON-метаданные — как в п. 4, с id боевых чартов (другие записи `chart_configuration`, если
   есть, оставить). CSS — файл 9 с боевыми id.
3. Нативные фильтры: у каждого в «Области действия» снимите эти четыре чарта (фильтры нужны
   другим вкладкам — выгрузкам, трансформеру). Если других вкладок нет — удалите.
4. Прежние датасеты `mdm_employee_d_detail_echarts`, `…_functional_echarts` и справочники
   `cross_filter_*_structure` новым чартам не нужны; удалять — только когда ими не пользуется
   ничто другое.

Откат — вернуть чартам списков прежние датасет, «Измерения» и JS (прежний JS — в выгрузке
дашборда 7241, ключ `jsx` у чартов 726821 и 795014), панели фильтров удалить.

## 8. Если что-то не так

| Симптом | Причина и что сделать |
|---|---|
| «Некорректный SQL запрос: →…←» при сохранении датасета | вставлен SQL прежней поставки или текст правили руками — файл целиком из этой поставки; не помогло — прислать фрагмент между стрелками |
| Выпадашка открывается поверх панели, а не справа от неё | CSS файла 9 не добавлен или id не заменены (`222222`, `333333` — id панелей фильтров) — п. 5 |
| Выпадашка открывается, но список под ней не закрыт / клик проходит в список | та же причина — п. 5 |
| «Применить» — список не меняется, через 30 с жёлтая плашка | панель фильтров не фильтрует список — п. 4 (`chartsInScope` у ID3 / ID4) |
| После «Применить» панель мигает загрузкой | в области панели остался сам чарт — п. 4: в `excluded` у ID3 должен быть ID3, у ID4 — ID4 (лишний запрос, не ошибка) |
| «Будет N» не совпал с итогом списка после «Применить» | в панели набраны «Период» или «Сотрудники по списку» — они пересчитываются после «Применить»; иначе прислать оба числа и фильтры |
| Жёлтая плашка в списке «Ответа нет 30 секунд…» при сортировке или колонках | список не фильтрует сам себя — п. 4 (`chartsInScope` у ID1 / ID2); на тяжёлом запросе (КП, 25 000) — запрос ещё идёт |
| Жёлтая плашка «Под фильтрами больше 25 000…» | так задумано: в таблицу помещается до 25 000 — сузьте фильтры |
| «В данных чарта нет колонок: …» | не все 5 полей в «Измерениях» или не синхронизированы столбцы — п. 1.3, 3.2 |
| «Нет служебной строки meta» | мал лимит строк — п. 3.2 |
| «Фильтры не применились: нет applyCrossFilter» | чарт открыт вне дашборда (в редакторе) — там фильтры не работают |
| «Для вашего логина нет строки в таблице доступа warden» | логина нет в `warden_access_array_cross` — как и у прежнего чарта |
| «Значений в фильтрах — не больше 200 у атрибута и 500 всего» | предел длины запроса ClickHouse; для длинных списков сотрудников — «Сотрудники по списку» (до 2 000) |
| Ошибка ClickHouse о колонке | колонка источника переименована — сверьте с прежним датасетом: новый читает те же колонки |
