# Детальные списки — что куда вставлять

Два чарта с одинаковой вёрсткой на двух вкладках одного борда: **«Детальные списки»**
(параллельная структура) и **«Детальные списки КП»** (каталог продуктов). У каждого свой
датасет, и каждый фильтрует сам себя: все фильтры — на полке слева внутри чарта (разделы
и порядок — как у нативных фильтров борда 7241), нативные фильтры борда не нужны.
Прежние датасеты и чарты не трогаются — новое заводится рядом, старый борд работает,
пока идёт проба на копии.

## Что нового (вторая поставка, 29.09)

Если первую поставку уже ставили — **замените целиком файлы 1–4** (SQL датасетов и JS
чартов). Больше в Proteus ничего не меняется: те же 5 колонок в «Измерениях», тот же
лимит 50 000, те же JSON-метаданные (п. 4), файл 5 — без изменений.

- **Исправлено: датасет не сохранялся** — «Некорректный SQL запрос: →… GROUP BY
  intDiv(rn - 1, 500) AS ch )…←». Proteus до ClickHouse разбирает SQL своим парсером
  (sqlglot), а тот не знает алиаса в `GROUP BY`, который ClickHouse принимает. Заодно убраны
  `\x`-экраны в строках: при перепечатке тем же парсером разделитель пути КП превращался в
  четыре знака, и фильтр КП молча ничего бы не находил. Теперь SQL разбирается sqlglot всех
  версий 23–30, а перепечатанный запрос отдаёт на стенде тот же ответ. **Файлы 1 и 2 —
  вставить заново целиком**, SQL в датасете заменить полностью (старый текст не дописывать).

- **Колонки — сразу, как сейчас:** строки приходят со всеми полями, «Колонки», пресеты,
  группировка по любой колонке — без запроса. Показаны по умолчанию MasterID и дата найма.
- **Фильтры — полкой слева**, как нативные: разделы «Основные», «Управленческая»,
  «Юридическая», «Атрибуты найма», «Каталог продуктов», «Региональные атрибуты»,
  «Другие атрибуты» в порядке борда 7241; у каждого фильтра своя выпадашка. «Применить» —
  внизу полки, всегда на виду. Полка сворачивается (««»), разделы — по заголовку.
- **Больше 25 000 под фильтрами** — жёлтая плашка над таблицей: «сузьте фильтры, чтобы
  загрузились все данные». До 25 000, но больше загруженного — «Загрузить всех».
- **Сортировка по умолчанию — MasterID по возрастанию.** У прежних датасетов сортировки
  нет вовсе (порядок строк случайный — зависит от того, как ClickHouse собрал ответ),
  поэтому «как сейчас» повторить нельзя; MasterID — устойчивый порядок, первая колонка.
- Цена «колонок сразу» — открытие тяжелее: ≈1–1,5 с и 13–20 МБ вместо ≈0,3 с и 0,1 МБ
  (замеры — п. 9).

## Как это работает

- **Открытие — один запрос:** итог «N сотрудников» и первые 5 000 сотрудников в порядке
  MasterID, сразу со всеми колонками (показаны MasterID и дата найма). Значения фильтров
  и деревья структур грузятся, когда их открывают (≈0,3–1 с), поиск юнита или значения —
  только найденным.
- **Полка фильтров слева** — разделы и порядок нативных фильтров борда 7241, у фильтра —
  подпись и выпадашка во всю ширину, заданный — синим с «×». Фильтры копятся (набранное —
  пунктиром) и уходят одной кнопкой «Применить · N» внизу полки; «Отменить» — вернуть
  применённые, «Сбросить все» — снять всё сразу. «Период» (последний день / на дату),
  «Численность», «Тип ЮЛ»; **«Юнит УС», «Юнит ЮС», «Продукт КП»** — вместо «Кросс-фильтр
  по …» и «Уровень 3…13»: дерево всех уровней и поиск по названию на любом уровне;
  **атрибуты** — у значения число сотрудников при остальных фильтрах (нули серым в
  конце — вместо каскадов); **«Сотрудники по списку»** — вставка MasterID, логинов,
  табельных или Siebel ID. Полка сворачивается в полоску, разделы — по заголовку.
- **Больше 25 000 под фильтрами** — жёлтая плашка над таблицей: сузьте фильтры, чтобы
  загрузились все. От загруженного до 25 000 — «Загрузить всех». «Загружать» — 5 000 /
  10 000 / 25 000.
- **Колонки** приходят все сразу: показать, убрать, пресеты «Персоналка», «Рабочие
  данные», у КП — «КП-разрез» — без запроса.
- **Сортировка:** все сотрудники загружены — сразу; нет — запрос «первые N по этой
  колонке».
- **Без запроса:** колонки, страницы, поиск по таблице, группировка (до 3 уровней),
  перестановка и ширина колонок, «Копировать» — все загруженные строки (с учётом поиска)
  для Excel.
- **Доступ — как раньше:** warden по логину маскирует персональные данные, грейд,
  сеньорность и оценку (в ячейке «⛔ нет доступа», в «Копировать» — прежний текст).
  Логина нет в warden — плашка вместо списка.
- **КП:** строки приходят по аллокациям; показана аллокация или уровень КП — блок
  сотрудника (поля сотрудника — одной ячейкой на блок), иначе — строка на сотрудника.
  «Суммарная аллокация» и «Кол-во аллокаций» считает чарт.

## 1. Датасеты

1. Proteus → Datasets → новый виртуальный датасет, база **CROSS** (та же, что у
   `mdm_employee_d_detail_echarts`), имя `detail_list`. SQL — файл 1 целиком →
   сохранить. Сохранение исполняет запрос с пустыми фильтрами и вашим логином — секунды.
2. То же — `detail_list_kp`, файл 2.
3. Колонок у каждого 5: `role, k, v, n, j`. Если SQL меняли у уже созданного датасета и
   колонки изменились — «Синхронизировать столбцы».
4. Проверка (необязательно): SQL Lab, база CROSS, файл 1 целиком → Run. Одна строка
   `meta` и десять строк `r` (5 000 сотрудников пачками по 500, все поля).

## 2. Копия борда

Копия дашборда 7241 (или новый дашборд) с двумя вкладками — «Детальные списки» и
«Детальные списки КП», на каждой один чарт из п. 3 во всю ширину, высота 1 000–1 400 px
(внутри чарт прокручивается сам). **Нативные фильтры в копии удалите все** — в новых
чартах их заменяет полка фильтров слева (те же разделы и порядок).

## 3. Чарты

Для каждого из двух:

1. Новый чарт на датасете `detail_list` (для КП — `detail_list_kp`), тип **ECHARTS**
   (кастомный JS). Можно взять копию прежнего чарта и сменить датасет.
2. **Измерения** — `role  k  v  n  j`, точными именами, в любом порядке. Мер нет.
   Сортировки нет. **Лимит строк — 50 000** (не меньше 25 000: у КП сейчас стоит 10 000 —
   мало, при открытых фильтрах пропадёт служебная строка meta). Серверная пагинация — выкл.
3. JS — файл 3 (для КП — файл 4) целиком. Сохранить.

## 4. Кросс-фильтр на себя

Без этого «Применить», сортировка, лимит и загрузка фильтров не работают —
через 30 секунд чарт сам скажет жёлтой плашкой. Мышкой в интерфейсе не настраивается,
правится JSON-метаданными дашборда (так настроен HRBP HUB):

1. **id чартов:** меню чарта «⋮» → «Редактировать график» — число после `slice_id=` в
   адресе. Ниже `ID1` — «Детальные списки», `ID2` — «Детальные списки КП».
2. Дашборд → «…» → «Редактировать свойства» → «Дополнительно» → «JSON метаданные».
3. `"cross_filters_enabled"` → `true` (нет ключа — добавьте строку `"cross_filters_enabled": true,`).
4. Блок `"chart_configuration"` замените целиком (нет — добавьте):
   ```json
   "chart_configuration": {
     "ID1": {
       "id": ID1,
       "crossFilters": {"scope": {"rootPath": ["ROOT_ID"], "excluded": [ID2]}, "chartsInScope": [ID1]}
     },
     "ID2": {
       "id": ID2,
       "crossFilters": {"scope": {"rootPath": ["ROOT_ID"], "excluded": [ID1]}, "chartsInScope": [ID2]}
     }
   },
   ```
   Каждый чарт фильтрует только себя: по умолчанию в `excluded` стоит сам чарт, и свой
   фильтр до него не доходит. В ключах `"ID1"`, `"ID2"` числа в кавычках, в остальных
   местах — без. Если чарт окажется и в области второго — данные не перепутаются (у
   носителей разные имена: `…_f` и `…_kf`), лишь добавятся лишние запросы.
5. Сохранить свойства → «Сохранить» дашборд → обновить страницу.

9. Логин без строки в warden — плашка вместо списка; с частичным доступом — «⛔ нет

## 7. Замена на проде

Когда проба прошла:

1. На боевом дашборде у двух чартов — датасет, «Измерения», лимит и JS, как в п. 1–3.
2. JSON-метаданные — как в п. 4, с id боевых чартов (другие записи `chart_configuration`,
   если есть, оставить).
3. Нативные фильтры: у каждого в «Области действия» снимите эти два чарта (фильтры
   нужны другим вкладкам — выгрузкам, трансформеру). Если других вкладок нет — удалите.
4. Прежние датасеты `mdm_employee_d_detail_echarts`, `…_functional_echarts` и
   справочники `cross_filter_*_structure` новым чартам не нужны; удалять — только когда
   ими не пользуется ничто другое.

Откат — вернуть чартам прежние датасет, «Измерения» и JS (прежний JS — в выгрузке
дашборда 7241, ключ `jsx` у чартов 726821 и 795014).

## 10. Что стендом не проверено

Боевые объёмы и время ClickHouse-кластера; размер деревьев в бою (УС ≈10 тыс. юнитов —
дерево приходит верхними тремя уровнями, глубже — раскрытием узла и поиском); поведение
двух чартов на соседних вкладках одного дашборда (у них разные `ns` и имена носителей —
состояние и фильтры не пересекаются); DOM борда для CSS (файл 5 необязателен).
