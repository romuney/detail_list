# FIELDS — поля для «Измерений» Proteus

Поля из SQL не попадают в `data` автоматически. Каждое поле ниже нужно вручную
добавить в панель «Измерения» с точным именем.

Правило синхрона: **имя в SQL == имя в «Измерениях» == ключ в `CFG.fields`**.
Любое расхождение — поле не дойдёт до графика (RETRO 17).

Типы в Proteus: `f(x)` — вычисляемое, `#` — число, `abc` — строка.

## Поля графика

Датасеты `detail_list`, `detail_list_kp` (списки) и `detail_list_flt`, `detail_list_kp_flt` (строки
фильтров) — один SQL `detail-list.data.sql`, файлы поставки 1–4. У всех четырёх чартов одни и те
же 5 полей — «Измерения», мер нет. Оси времени нет:
период — фильтр «Период», даты для него приезжают в meta строками `YYYY-MM-DD`.

| Поле (точное имя) | Тип | Назначение | Обязательно | Добавлено в «Измерения» |
|---|---|---|---|---|
| `role` | abc | Роль строки: meta, r (список); meta, F, T, s, q, fq (строка фильтров) | да | нет |
| `k` | abc | Ключ по роли: режим у meta, атрибут у F/fq, дерево у T/q/s, номер пачки у r | да | нет |
| `v` | abc | Значение по роли: метка запроса у meta, число значений у F, «пачка:узлов» у T, id узла | да | нет |
| `n` | # | Число: сотрудников под фильтрами у meta, при остальных фильтрах у f/t/q, строк в пачке у r | да | нет |
| `j` | abc | Пакет: JSON у meta, base64 от UTF-8 у r (строки списка), F (значения атрибута), T (узлы дерева); поля узла через \t у q/s | да | нет |

Даты сотрудников (дата найма, рождения и т. п.) — не колонки, а поля внутри пачек `r`
строками `YYYY-MM-DD`; чарт показывает их как ДД.ММ.ГГГГ.

Последняя колонка — не украшение: пока там «нет», поле физически отсутствует в `data`,
и в JS будет `undefined`. Чарт сам пишет, каких полей не хватает.

## Что считается в JS, а что в SQL

| Расчёт | Где считается | Почему | Кто согласовал |
|---|---|---|---|
| Отбор и серверная сортировка первых N сотрудников, итог под фильтрами | SQL | 100 тыс. сотрудников в браузер не везутся — только первые N | пользователь: «по умолчанию 5 000, до 25 000» |
| Маски warden (персональные данные, грейд, сеньорность, оценка) | SQL | доступ не должен зависеть от браузера; логика прежнего датасета слово в слово | требование «не слабее текущей» |
| Значения фильтров со счётчиками, деревья УС / ЮС / КП, поиск | SQL | считаются по всей таблице, не по загруженным строкам | пользователь: «без доп датасетов» |
| Страницы, поиск и сортировка загруженного, группировка, сумма и число аллокаций | JS | без запроса, по загруженным строкам | по умолчанию |
| Колонки списка | SQL по запросу (`cols`) | открытие — две колонки, быстрее | пользователь, 30.09: «если доп. прогрузка недолгая, но ускорит загрузку по умолчанию — можно» |
| Все значения фильтров и деревья со счётчиками при остальных фильтрах | SQL, вид filters, одним ответом | открыть фильтр — без запроса | пользователь, 30.09: «фильтры и значения прогружены сразу, и влияние фильтр на фильтр» |

## Статические значения (не из SQL)

## Настроить РУКАМИ в Proteus (skill этого не делает)

Это задачи ПОЛЬЗОВАТЕЛЯ, а не агента. Агент оставляет их пустыми `[ ]` и заполняет
только текст в скобках. Ставить `[x]` за пользователя ЗАПРЕЩЕНО: галочка означает
«в Proteus реально настроено», и ложная отметка прячет причину пустого виджета.

- [ ] Тип визуализации: ECHARTS (кастомный JS: файлы 5–8 — списки и строки фильтров).
- [ ] Измерения: все 5 полей из таблицы выше, точными именами.
- [ ] Сортировка: [не нужна — чарт раскладывает строки по role сам; метрик-сортировки не добавлять].
- [ ] Упорядочивание: [пусто].
- [ ] Сортировка по убыванию: [выкл].
- [ ] Лимит строк: [50 000 — не меньше 25 000: значения фильтров приходят тысячами строк, meta должна приезжать всегда].
- [ ] Серверная пагинация: [выкл].
- [ ] Фильтры: [нативных нет — строка фильтров отдельным чартом над списком; области кросс-фильтров четырёх чартов — JSON-метаданные дашборда, инструкция поставки п. 4; CSS разворота — файл 9].
